# Writify Studio

### Research. Write. Verify.

**Writify Studio** is a multi-agent content intelligence platform that transforms a single topic into a complete, research-backed content package.

Instead of handling research, writing, SEO, social media adaptation, and fact-checking separately, Writify Studio coordinates a specialised team of AI agents through a single workflow.

---

## What Writify Studio Does

Enter a topic, choose your preferred content formats, select the language and writing preferences, and let the multi-agent pipeline handle the rest.

The platform can produce:

* Research-backed blog posts
* LinkedIn posts
* Twitter/X threads
* SEO optimisation reports
* Fact-checking reports
* Research summaries with sources

Research runs first, and only the content agents required for the selected deliverables are executed.

While the agents work, the interface shows a **live Agent Workflow Board** so you can watch every stage of the run in real time (see [Live Agent Workflow Board](#live-agent-workflow-board)).

---

## Multi-Agent Team

Writify Studio uses six specialised agents, each responsible for a specific stage of the content workflow.

| Agent                | Responsibility                                                                                   |
| -------------------- | ------------------------------------------------------------------------------------------------ |
| **Researcher**       | Searches the web, gathers relevant information, identifies trends, and prepares sourced research |
| **Blog Writer**      | Converts research into a structured, audience-focused blog post                                  |
| **LinkedIn Writer**  | Creates a professional LinkedIn post with a strong hook and CTA                                  |
| **Twitter/X Writer** | Produces a concise 6–8 post thread                                                               |
| **SEO Editor**       | Optimises the blog and generates SEO metadata and keyword recommendations                        |
| **Fact-Checker**     | Reviews key claims, verifies evidence, and identifies unsupported or incorrect information       |

The agents work sequentially so that downstream content is based on the research produced earlier in the pipeline.

## Key Features

### Research First

The Researcher agent performs multiple web searches using DuckDuckGo and creates a research foundation containing:

* Sourced facts
* Relevant trends
* Topic outline
* Research sources
* Supporting evidence

The application also records returned source URLs directly from the search layer rather than relying on URLs generated by the language model.

### Flexible Deliverables

Users can select any combination of:

* Blog Post
* LinkedIn Post
* Twitter/X Thread
* SEO Report
* Fact-Check

Research is automatically included in every generation run.

If SEO is selected, the Blog Post is automatically added because SEO optimisation depends on the generated article.

### Multiple Output Languages

Generated content can be produced in:

* English
* Urdu
* Roman Urdu
* Custom language 

The application interface itself remains in English.

### Writing Controls

Users can customise:

* AI model
* Output language
* Tone of voice
* Blog length
* Target audience
* Focus keywords

### SEO Analysis

The SEO Editor provides:

* SEO title
* Meta description
* URL slug
* Primary keyword
* Secondary keywords
* Internal/external link suggestions
* Image alt-text suggestions
* SEO-optimised blog content

### Fact-Checking

The Fact-Checker reviews important claims and provides:

* Claim
* Verdict
* Supporting evidence
* Required correction
* Reliability score

Verdicts include:

* Verified
* Unverified
* Incorrect

The fact-checking process is designed to identify uncertainty rather than automatically approve every claim.

### Google Exploration

The Research section provides quick Google exploration links for:

* Topic overview
* Statistics
* Current-year trends
* News
* Google Scholar
* User-provided keywords

### Source Transparency

Research sources are displayed in the application with:

* Source title
* Domain
* Clickable URL

Sources are also included in the downloadable research output.

### Live Agent Workflow Board

Writify Studio does not hide what the agents are doing. When you press **Generate content**, a visual board appears on the front end and updates live while the run is in progress. After the run finishes, the same board stays available inside an expander named **"Agent workflow: how this run was processed"**, placed above the result tabs.

The board is built from a trace of what really happens in the run (plan, retrieval, each agent, guard, delivery). It is not a fake animation: every status, timing, source count and output shown on it comes from the actual pipeline.

**What the board shows**

| Part | What you see |
| ---- | ------------ |
| **Your query** | The topic, plus chips for the language, tone, blog length and target audience used for this run |
| **Phase strip** | Five phases that light up in order: Plan, Retrieve (RAG), Agents write, Guard, Deliver |
| **1. Plan** | Which outputs you selected and which agents will actually run. If SEO is selected without Blog, a note explains that the Blog Writer runs in the background and is not shown in the results |
| **2. Retrieve** | The web searches that were made (with the number of sources each one returned), a collapsible list of the collected sources with titles and domains, and a short explanation of how this evidence flows into the agents and the Guard |
| **3. The agent crew** | One card per agent (see below) |
| **4. Guard** | The result of the code-level check of links and numbers against the real sources, listing any fixes that were applied |
| **5. Deliver** | The final deliverables with their word counts |
| **Event timeline** | A collapsible, time-stamped log of the run (for example "Started", "Finished", "Guard", "Delivered") |

**The agent crew**

Each of the six agents is shown as an animated robot sitting at its own desk with a small monitor:

* **Not selected**: the agent is greyed out and compact, with a note that its output was not selected.
* **Standby**: the agent is waiting for its turn.
* **Working...**: the robot types, the monitor shows a live "writing" animation and the card is highlighted.
* **Done in X s**: the monitor shows the first lines of the real output and the time the agent took.

Every active card also explains the agent's job:

* **Gets**: what the agent receives as input (for example the number of real web sources, the research report, the blog draft, or every generated deliverable for the Fact-Checker)
* **Tool**: the tool it uses (for the Researcher: DuckDuckGo search)
* **Runs as**: shown when the lean mode groups several writers into one request
* **Returns**: the exact output format the agent produces

Two collapsible sections on each finished card let you inspect the run in detail:

* **Prompt this agent received**
* **Output it produced**

**Lean mode**

To stay within the Gemini free tier, the Blog, LinkedIn, Twitter/X and SEO writers can run as a single request handled by the Content Studio Writer. The board shows this clearly, and those agents start and finish together.

**Other behaviour**

* If the same inputs were used in a recent run, the result is served from cache and the board states this in the timeline.
* If a run stops before delivery, the phase strip turns to an error state and a message explains that nothing was lost.
* The board is plain HTML and CSS (no JavaScript) rendered in its own frame, so it displays reliably in Streamlit.
* Animations are switched off automatically for users who prefer reduced motion.
* The board can never break a generation: all its hooks are wrapped so that a display error is ignored by the pipeline.

### Export

Individual outputs can be downloaded as Markdown files.

The complete generated content package can also be downloaded as a ZIP archive.

### Main Files

**`app.py`**
Contains the Streamlit interface, session state, generation workflow, output tabs, downloads, history, and UI styling.

**`crew_setup.py`**
Defines the CrewAI agents, tasks, model configuration, and dynamic crew pipeline. It also reports each step of the run to the Agent Workflow Board.

**`tools.py`**
Contains the DuckDuckGo search tools and source collection logic.

**`agent_viz.py`**
Contains the Agent Workflow Board: the trace that records what happens during a run and the HTML/CSS that draws the live board (phase strip, agent crew, guard, delivery and event timeline).

**`requirements.txt`**
Contains the Python dependencies required to run the application.

**`PROMPT.md`**
Contains the master prompt used to reproduce the application architecture and feature set.

## AI Model Configuration

The application keeps supported Gemini models in a central model dictionary so model names can be updated without changing the rest of the application.

Example:

```python
MODELS = {
    "Recommended": "gemini/...",
    "Fast": "gemini/...",
    "Fast Lite": "gemini/..."
}
```

The selected model is passed to CrewAI through the Gemini integration.

No temperature value is forced; the model uses its default generation behaviour.

## API Key Setup

Writify Studio requires a Gemini API key.

Create a free API key through Google AI Studio.

The application reads the key from either:

* Streamlit secrets
* Environment variables / `.env`

The API key is never displayed in the application interface.

### Environment Setup

Create a `.env` file:

```env
GEMINI_API_KEY="your_api_key_here"
```

Never commit your real API key to GitHub.

## Run Locally

### 1. Clone the repository

```bash
git clone <your-github-repository-url>
cd writify-studio
```

### 2. Create a virtual environment

#### Windows

```bash
python -m venv .venv
.venv\Scripts\activate
```

#### macOS / Linux

```bash
python3 -m venv .venv
source .venv/bin/activate
```

### 3. Install dependencies

```bash
pip install -r requirements.txt
```

### 4. Configure the API key

Copy the example environment file:

```bash
cp .env.example .env
```

On Windows, you can simply create `.env` manually and add:

```env
GEMINI_API_KEY="your_api_key_here"
```

### 5. Start the application

```bash
streamlit run app.py
```

The application will open in your browser.

## Streamlit Community Cloud Deployment

Writify Studio can be deployed directly from GitHub using Streamlit Community Cloud.

### Step 1 — Push the project to GitHub

Upload the complete project repository to GitHub.

### Step 2 — Create a Streamlit app

Open Streamlit Community Cloud and create a new application.

Select:

```text
Repository: your GitHub repository
Branch: main
Main file: app.py
Python version: 3.11
```

### Step 3 — Add the API key

Open the application's **Settings → Secrets** and add:

```toml
GEMINI_API_KEY = "your_api_key_here"
```

### Step 4 — Deploy

Save the secret and deploy the application.

The API key remains outside the source code and is not displayed in the application.

## Reliability & Error Handling

Because the application uses a free-tier Gemini setup, model availability and request limits can vary.

Writify Studio includes handling for common API conditions such as:

* Temporary server unavailability
* Rate limits
* Quota limits
* Model availability issues
* Invalid API keys
* General generation errors

The application can retry supported failures and fall back to another configured Gemini model when appropriate.

The CrewAI configuration also uses a request-per-minute limit suitable for the free-tier workflow.

---

## Security

Writify Studio follows a simple API-key handling model:

* API keys are loaded from environment variables or Streamlit secrets.
* API keys are not displayed in the UI.
* API keys should never be committed to GitHub.
* `.env` is excluded through `.gitignore`.
* Streamlit secrets are kept outside the repository.

## Important Notes

### Gemini Free Tier

Gemini's free tier has usage and rate limits. Heavy generation workflows may require waiting before trying again.

The application uses a controlled request rate to reduce unnecessary API failures.

### Search Results

Search results are collected by the application's DuckDuckGo tools.

The Researcher is instructed to use retrieved evidence rather than inventing sources, URLs, or statistics.

### Generated Content

AI-generated content should still be reviewed by the user before publication, especially for factual, technical, financial, legal, or time-sensitive topics.

Traditional content creation often requires moving between multiple tools:

Writify Studio brings these stages into one coordinated multi-agent workflow:
